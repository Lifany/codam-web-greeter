# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A LightDM greeter theme (`codam-web-greeter`) for nody-greeter / web-greeter, built for 42 campuses (originally Codam). It acts as both the login screen and the lock screen, shows Intra events/exams, enforces exam mode, and auto-logs-out idle users. The repo has three parts that work together:

- `client/` — TypeScript greeter UI, bundled by webpack into `dist/bundle.js` (target `electron-renderer`, runs inside nody-greeter).
- `server/` — Express back-end that talks to the 42 Intra API and serves config/exam data to campus machines.
- `systemd/` — install scripts and system/user services that run on each campus machine to bridge the client, server, and OS.

## Commands

There is no test suite and no linter. "Testing" is building successfully plus manual testing in the greeter.

Client (from repo root):
```bash
make                                            # clean, npm install, tsc, webpack → dist/ (dark theme)
make CLIENT_THEME=light                         # light theme
make CLIENT_THEME=light CLIENT_THEME_BOXED=boxed  # light + boxed login form
npm run bundle-dev                              # webpack dev build only (assumes static/greeter.css exists)
sudo make install                               # build, copy to /usr/share/web-greeter/themes/codam, run systemd/install.sh
```
CI builds all four theme × boxed combinations (`.github/workflows/client-webpack.yml`); a change should build in each.

Server:
```bash
cd server && cp .env.example .env && echo '{}' > messages.json
npm install && npm run build && npm run start   # listens on :3000
make server        # (repo root) syncs server version to client's, then docker compose up -d (nginx on 443/80)
make server-stop
```
CI (`server-test.yml`) only checks that the server builds and `GET /` responds.

Debugging the client: opening `static/index.html` in a browser loads `static/debug.js` as a fallback when `bundle.js` is missing, giving a static mock with a screen switcher. For real behavior, install the theme and run `nody-greeter --debug` (requires `X-LightDM-Allow-Greeter=true` in `/usr/share/xsessions/ubuntu.desktop`; remove it afterward — it's a security risk). `dev/forever-exam.data.json` is a sample `data.json` for exercising exam mode.

## Architecture

### Data flow (client never calls the server directly)
1. `server/` fetches events/exams from Intra via `@codam/fast42`, caches them (node-cache, 15 min), and serves `/api/config/:hostname?`. Exams are matched to hosts by IP range (`server/src/utils.ts`). Per-host messages come from `server/messages.json`.
2. On each campus machine, the `codam-web-greeter.timer` runs `systemd/system/codam-web-greeter-fetcher.sh`, which reads `data-server-url` from the theme's `settings.ini`, appends the hostname, curls it, and writes `/usr/share/web-greeter/themes/codam/data.json`.
3. The client (`client/data.ts`) reads the local `data.json` every 5 minutes via XMLHttpRequest and notifies listeners (`addDataChangeListener`).

### Client structure
- `client/main.ts` — entry; on the `GreeterReady` event creates singletons attached to `window` (`window.data`, `window.auth`, `window.ui`, `window.idler`) and registers keybinds (Ctrl+Alt+Del reboot, Ctrl+Alt+E override exam mode, Ctrl+Alt+D debug keys, F1/F2 brightness). Other modules reach each other through these globals (e.g. `window.ui.setDebugInfo(...)` for on-screen error reporting).
- `client/ui.ts` — decides mode: if LightDM reports a logged-in user it's the **lock screen** (`LockScreenUI`); otherwise **login screen** (`LoginScreenUI`) plus `ExamModeUI`, which takes over when `exams_for_host` contains an exam starting within 20 minutes.
- `client/uis/screen.ts` — abstract `UIScreen` base class for the three screens in `client/uis/screens/`.
- `client/auth.ts` — wraps LightDM's authentication flow.
- LightDM/greeter APIs come from `nody-greeter-types` (`window.lightdm`, `window.theme_utils`). File existence checks use `theme_utils.dirlist`, not fs.

### OS integration via /tmp files
The greeter runs as the `lightdm` user and can't read the user's home, so user-session services (`systemd/user/`) copy things into `/tmp`:
- `/tmp/codam-web-greeter-user-avatar` (from `~/.face`) and `/tmp/codam-web-greeter-user-wallpaper` (Gnome screensaver image) — read by the lock screen.
- `/tmp/codam_web_greeter_lock_timestamp_<user>` — written when the lock screen appears.

The 42-minute auto-logout is enforced by `systemd/system/codam-web-greeter-idler.sh` (timer-driven, uses `xprintidle` and the lock timestamp), not by the client. `client/idler.ts` only tracks in-greeter idleness. Paths shared between client and scripts are hardcoded on both sides — change them together.

### Styling
`static/greeter.css` is generated by the Makefile: it imports `css/styles.css` plus `css/dark.css` or `css/light.css`, and optionally `css/boxed.css`. Edit the source CSS files, not `greeter.css`. Everything in `static/` is copied verbatim into `dist/`.

### Versioning
The client `package.json` version is the source of truth; `server/match_versions.sh` (run by `make server`) copies it into `server/package.json`.
